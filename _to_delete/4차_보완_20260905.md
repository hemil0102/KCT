## ① 같은 다섯 문제만 나온다 — `nextDueAt` 이 죽어 있다

### 무엇이 일어났나

로그 279~293 (세 회차)의 문항이 **전부 1·2·3·4·5** 다.

### 왜

`SessionBuilder.isDueEarlier` 는 이렇게 정렬한다.

```swift
let left  = progressByID[lhs.id]?.nextDueAt ?? .distantPast
let right = progressByID[rhs.id]?.nextDueAt ?? .distantPast
if left != right { return left < right }
return (lhs.difficulty, lhs.id) < (rhs.difficulty, rhs.id)
```

`nextDueAt` 은 **아무도 넣어 주지 않는다.** `record()` 를 셋으로 나눌 때 그 줄이 빠졌고, 8/31 에 「어머니 결과와 논문을 보고 나중에 다시 설계하자」고 미뤄 두었다.

그래서 **모두 `nil` → 모두 `.distantPast` → 늘 무승부 → 번호순.** 20문항을 다 틀리면 20개가 전부 복습 대상이 되는데, 그중 늘 앞의 다섯만 뽑힌다.

> 정답을 맞히면 마스터로 올라가 복습 큐에서 빠지므로 이 결함이 여태 안 보였다. **다 틀려 보니 드러났다.**

### 고치는 법 — `lastSeenAt` 을 2순위로

`nextDueAt` 을 되살리는 일(간격 재설계)은 그대로 미뤄 둔다. 대신 **무승부를 번호가 아니라 「오래 안 본 것」이 이기게** 한다.

**`KCT/Session/SessionBuilder.swift`** 의 `isDueEarlier` (274줄). 마지막 줄

```swift
        return (lhs.difficulty, lhs.id) < (rhs.difficulty, rhs.id)
```

이 줄 **바로 위**에 넣는다.

```swift
        let leftSeen = progressByID[lhs.id]?.lastSeenAt ?? .distantPast
        let rightSeen = progressByID[rhs.id]?.lastSeenAt ?? .distantPast
        if leftSeen != rightSeen { return leftSeen < rightSeen }

```

- `lastSeenAt` 은 `countAttempt` 가 **이미 넣고 있다.** 새로 만들 것이 없다
- 한 번도 안 나온 문항은 `nil` → `.distantPast` → **가장 먼저** 나온다. 원하는 대로다
- `nextDueAt` 이 나중에 살아나도 **1순위가 그대로**라 이 줄은 그냥 2순위로 남는다

이제 회차를 돌 때마다 **가장 오래 안 본 다섯**이 나온다.

## ② 「~는 관련이 없습니다」 — 금지하려고 적은 문장을 따라 쓴다

### 무엇이 일어났나

```
"고조선을 세운 사람은 단군왕검입니다. 그는 아사달을 도읍지로 삼았습니다.
 단군왕검은 관련이 없습니다."                          ← 정답을 두고 관련 없다고 한다
"정답은 고조선입니다. '고'는 옛날이라는 뜻입니다."      ← 「정답은」으로 시작
```

### 왜 — 내 지침이 원인이다

공통 규칙 3에 이렇게 적혀 있다.

```
3. 다른 보기나 다른 날, 다른 인물을 끌어오지 않는다.
   "~는 관련이 없습니다" 같은 문장은 쓰지 않는다.
```

**금지할 문장을 따옴표로 적어 눈앞에 보여 줬다.** 작은 모델은 「쓰지 마라」라는 부정보다 **문장의 모양**을 먼저 따라간다. 그래서 이번에는 주어까지 잘못 골라 「단군왕검은 관련이 없습니다」가 됐다.

「'안'은 옛날이라는 뜻」이 예시 하나 때문에 퍼졌던 것과 **같은 종류의 실수**다. 그때는 좋은 예를 잘못 고른 것이고, 이번은 나쁜 예를 보여 준 것이다.

### 고치는 법 — 금지 문장을 지우고, 할 일을 적는다

**`KCT/Grading/CommentaryWriter.swift`** 의 `instructions` (68줄) 안. `[반드시 지킨다]` (75줄) 부터 `"""` 직전까지를 통째로 교체.

```swift
            [반드시 지킨다]
            1. 세 문장을 넘기지 않는다.
            2. 정답을 문장 안에 그대로 넣는다.
            3. 세 문장을 모두 정답을 설명하는 데에만 쓴다.
            4. 정답이 아닌 것은 아예 말하지 않는다.
            5. 첫 문장은 정답이 무엇인지로 시작한다.
            6. 마지막 문장까지 설명으로 채운다.
            7. 확실하지 않은 연도, 숫자, 글자 뜻은 넣지 않는다.
               확실하지 않으면 그것이 무엇을 하는 것인지만 말한다.
```

바뀐 점 셋.

- **금지 문구를 인용하지 않는다.** 「~는 관련이 없습니다」, 「다음에는」, 「잘 기억하세요」를 지운다. 적어 두면 따라 쓴다
- **부정을 「할 일」로 바꾼다.** "격려하지 마라" → **"마지막 문장까지 설명으로 채운다"**
- **「정답은」으로 시작하지 않게** 5번을 넣는다. 「정답은 고조선입니다」는 채점 결과를 읊는 말이지 설명이 아니다

> **여기서 배운 것** — 작은 모델의 지침에는 **하지 말 것을 문장으로 적지 않는다.** 그 자리에 「대신 무엇을 할지」를 적는다. 예시는 **좋은 예만** 보여 준다.
