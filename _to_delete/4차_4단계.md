# 4차 프로토타입 · 4단계 — 해설을 다시 쓰고, 모달을 손본다

> 3단계까지 : 모달이 뜨고 해설이 보인다
> 4단계 : 해설이 **되풀이가 아니라 기억할 고리**를 주게 하고, 색으로 정답을 각인시킨다

---

## 로그에서 본 것 (2026-09-05, 12줄)

| 증상 | 몇 줄 | 왜 |
|---|---|---|
| 「다음에는 잘 기억하세요」로 끝난다 | 9 / 12 | 지침 5를 어겼다 |
| 「광복절은 관련이 없습니다」처럼 고른 답을 되짚는다 | 8 / 12 | 지침 4를 어겼다 |
| 네 문장 | 6 / 12 | 「두 문장 이내」를 어겼다 |
| 질문을 되풀이할 뿐 새 고리가 없다 | 대부분 | **지침에 아예 없던 요구다** |

```
문제 "우리나라 최초의 국가는?"
해설 "우리나라에서 가장 오래된 나라는 고조선입니다. 이 나라는 아주 옛날에
      처음 시작되었습니다. 무궁화는 이 나라와는 다른 이야기입니다."
```

세 문장이 다 **질문을 바꿔 말한 것**이다. 어머니가 이걸 읽고 새로 얻는 것이 없다.

### 무엇이 원인이었나

**프롬프트에 「고르신 답」을 넘겨줬다.** 주면 쓴다. 규칙으로 「쓰지 마라」고 해도, 눈앞에 있는 정보를 안 쓰기는 어렵다.

그래서 이번에는 **아예 안 알려준다.** 모델이 모르는 것은 말할 수 없다. 규칙을 늘리는 것보다 **말할 재료를 치우는 쪽**이 확실하다.

### 「고르신 답」이 사라지는 것이 아니다

세 자리를 갈라 둔다. **모델에게만 안 넘긴다.**

| 어디 | 고르신 답 | 왜 |
|---|---|---|
| **모달 화면** | **그대로 보인다** (주황, ④ⓐ) | 「내가 무엇을 골랐더라」를 한 번 확인하고 넘어간다 |
| **로그 `chosen`** | **그대로 남는다** | 같은 분류에서 골랐나 다른 분류에서 골랐나 — 진단의 핵심 지표다 |
| **모델 프롬프트** | **안 넘긴다** | 넘기면 해설 안에 「~는 관련이 없습니다」가 끼어든다 |

## ① `KCT/DesignSystem/AppColor.swift`

`mastered` 아래에 두 줄.

```swift
    /// 어머니가 고른 답을 적을 때. 시그니처(보라)와 반대편의 주황.
    static let chosenAnswer = Color(red: 0.80, green: 0.44, blue: 0.10)

    /// 정답을 각인시키는 연두. 정답이 나오는 모든 자리에 같은 색을 쓴다.
    static let answerAccent = Color(red: 0.33, green: 0.61, blue: 0.16)
```

- **`correct`(진초록)와 다른 색이다.** `correct` 는 결과 화면의 「맞음」 표시고, `answerAccent` 는 **정답이라는 글자 자체**를 칠하는 색이다. 하나로 합치면 나중에 한쪽만 바꾸고 싶을 때 둘 다 바뀐다.
- 흰 배경에서 어르신이 읽을 수 있는 만큼만 어둡게 잡았다. 더 밝은 연두는 예쁘지만 안 보인다.

```swift

```

**ⓑ 정답 색을 연두로** — `Text(feedback.correctAnswer)` 의 `foregroundStyle` 한 줄

```swift

```

**ⓒ 해설 안의 정답도 같은 연두로** — `ScrollView` 안의 `Text` 를 이렇게

```swift
                Text(commentaryText)
                    .font(.system(size: 24, weight: .medium))
                    .foregroundStyle(.black)
                    .lineSpacing(8)
                    .frame(maxWidth: .infinity, alignment: .leading)
                    .opacity(feedback.isReady ? 1 : 0.4)
```

그리고 `body` 아래에 이 계산 프로퍼티를 새로 넣는다.

```swift
    /// 해설에서 정답과 같은 글자를 찾아 연두로 칠한 문장.
    ///
    /// 정답이 **세 곳**(제목·큰 글씨·해설 속)에서 같은 색으로 보이면
    /// 눈이 그 색을 「정답」으로 배웁니다. 한 곳만 칠하면 그냥 장식이 됩니다.
    ///
    /// - Note: 첫 번째만이 아니라 **나오는 곳마다** 칠합니다.
    private var commentaryText: AttributedString {
        var text = AttributedString(feedback.commentary)
        var searchStart = text.startIndex

        while searchStart < text.endIndex,
              let found = text[searchStart..<text.endIndex].range(of: feedback.correctAnswer) {
            text[found].foregroundColor = AppColor.answerAccent
            text[found].font = .system(size: 24, weight: .bold)
            searchStart = found.upperBound
        }
        return text
    }
```

## 다 넣고 확인할 것

1. **고르신 답이 주황**, 정답이 **연두**, 해설 속 정답도 **같은 연두**로 굵게.
2. 모달이 화면 **절반**만 차지한다.
3. 해설이 **세 문장 이내**다.
4. 해설에 **「다음에는」·「잘 기억하세요」가 없다.**
5. 해설에 **고른 답이 안 나온다.** — 모델이 아예 모르므로 나올 수가 없다.
6. 해설이 질문을 되풀이하지 않고 **새로 알려주는 것이 있다.**

6번이 이번 단계의 핵심이다. 12줄쯤 모아서 「이걸 읽고 새로 아는 게 있나」를 하나씩 본다.

```sql
select question_id, explanation
from obs_record
where is_correct = false and explanation is not null
order by id desc limit 20;
```

## 남은 걱정

- **모델이 지어낼 수 있다.** 「'고'는 옛날이라는 뜻」은 맞지만, 다른 문항에서 틀린 풀이를 내놓을 수 있다. 지침 6으로 막아 두었으나 **완전하지 않다.** 어머니에게 보이기 전에 20문항을 다 읽는 이유가 이것이다.
- **높이 0.5 에서 해설이 잘릴 수 있다.** 세 문장이면 대개 들어가지만, 잘리면 `ScrollView` 안에서 스크롤된다. 실제로 보고 답답하면 0.6 으로 올린다.
