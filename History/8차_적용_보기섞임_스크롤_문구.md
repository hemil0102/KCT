# 인물 보기 섞임 분석 + 스크롤 인디케이터 + 문구 변경

> 다 넣으면 지워도 되는 임시 메모입니다.

## ① 인물 문제에 다른 종류가 섞이는 이유 — 분석

**결론부터**: `atLeast minimum` 문턱을 3으로 딱 고정해 둔 것과, "자기 자신을 뺀다"를
**id로** 했던 것, 이 두 가지가 겹쳐서 생긴 일입니다. 어느 하나 때문이 아니라 **우연히
겹쳐서** 문제(단군왕검)는 잘 되고 다른 문제(안익태·주몽)는 안 됐던 겁니다.

### 실제 데이터로 확인한 것

지금 문제집(30문항)에서 인물(kind: `.person`)은 **6문항, 그런데 답은 3개뿐**입니다.

| id | 문제 | 답 |
|---|---|---|
| 3, 4, 5, 6 | (표현만 다른 같은 질문 네 개) | **단군왕검** |
| 10 | 고구려를 세운 왕(활 잘 쏨) | **주몽** |
| 20 | 애국가를 작곡한 사람 | **안익태** |

`answerPool(preferringKindOf:)`는 "자기 자신"을 **id**로 뺐습니다. 그래서:

- **단군왕검 문제(예: id 4)** → id만 다르고 답은 같은 형제 문항(3,5,6)이 셋이나 있어서,
  그 답("단군왕검")까지 포함해 좁힌 모음이 `{단군왕검, 주몽, 안익태}` = **3개** → 문턱(3)을
  **딱 통과** → 그대로 사용. 나중에 정답("단군왕검")은 어차피 보기에서 빠지니
  실제로는 `{주몽, 안익태}` 두 명 중 필요한 만큼 뽑힘. **인물만 나온 이유**입니다.
- **안익태 문제(id 20)** → 형제 문항이 없어서 좁힌 모음이 `{단군왕검, 주몽}` = **2개** →
  문턱(3)에 **못 미침** → **전체 정답 모음으로 통째 되돌아감** → 거기서 무작위로 뽑혀
  "삼일절" 같은 게 섞여 나온 것입니다.
- **주몽 문제(id 10)**도 같은 이유로 `{단군왕검, 안익태}` = 2개라 되돌아갔고, "고조선"이
  섞였습니다.

즉 **"인물끼리만 있으면 3개는 돼야 믿는다"는 문턱이, 정작 몇 개가 필요한지와 무관하게
고정돼 있었던 게 진짜 원인**입니다. 2지선다는 오답이 **1개**만 있으면 되는데, 문턱은
항상 3이었습니다. 그리고 문턱을 넘지 못하면 "그나마 있는 인물 두 명"조차 안 쓰고
**통째로 포기하고 전체로 돌아간 것**도 너무 과했습니다.

### 고칠 방향

1. **필요한 개수만큼만 요구한다** — 2지선다는 1개, 4지선다는 3개. 지금처럼 무조건 3을
   요구하지 않습니다.
2. **모자라도 있는 만큼은 쓰고, 모자란 자리만 다른 데서 채운다** — 통째로 포기하지
   않습니다. 인물이 2명뿐이면 2명은 쓰고, 부족한 1자리만 다른 종류에서 채웁니다.
3. 자기 자신을 뺄 때 **id가 아니라 답 자체(displayAnswer)로** 뺍니다 — 표현만 다른
   같은 질문(3,4,5,6)이 우연히 실제보다 넉넉해 보이게 만드는 일을 막습니다.

이렇게 하면 인물 문제 **셋 다 일관되게** 동작합니다 (2지선다는 항상 인물끼리,
4지선다는 인물 2명 + 다른 데서 1명 — 인물 자체가 3개뿐이라 이게 지금 데이터로 낼 수
있는 최선입니다. 인물 문항을 더 늘리면 이 마지막 한 자리도 인물로 채워집니다).

### 넣는 순서

#### ⓐ `KCT/Data/QuestionCatalog.swift` — `answerPool(preferringKindOf:atLeast:)` 함수를 통째로 바꿉니다

**지금 코드**

```swift
func answerPool(preferringKindOf question: Question, atLeast minimum: Int = 3) -> [String] {
    let narrowed = Set(
        questions
            .filter { $0.kind == question.kind && $0.id != question.id }
            .map(\.displayAnswer)
    )
    return narrowed.count >= minimum ? Array(narrowed) : answerPool
}
```

**바뀔 코드**

```swift
/// 같은 종류(``Question/kind``)를 최대한 채우고, 모자란 자리만 다른 데서 채운 정답 모음.
///
/// 지금 문제집은 종류별 문항 수가 적어서(인물은 6문항인데 답은 3개뿐) 필요한 오답
/// 개수를 그 종류 안에서 다 못 채울 때가 있습니다. 그때 전체 모음으로 통째 돌아가면
/// 「안익태」의 오답으로 「삼일절」 같은 게 나와 오히려 더 쉬워집니다. 그래서
/// **있는 만큼은 같은 종류를 쓰고, 모자란 자리만** 무작위로 채웁니다.
///
/// - Parameter count: 이번 문제에 실제로 필요한 오답 개수. 2지선다는 1, 4지선다는 3
///   — 필요한 만큼만 요구해야 "인물이 2명뿐이라 아쉽지만 못 쓴다"는 일이 안 생깁니다.
func answerPool(preferringKindOf question: Question, count: Int) -> [String] {
    let sameKind = Array(Set(
        questions
            .filter { $0.kind == question.kind && $0.displayAnswer != question.displayAnswer }
            .map(\.displayAnswer)
    ))
    guard sameKind.count < count else { return sameKind }

    // 모자란 자리만 다른 종류에서 무작위로 채운다.
    let filler = answerPool
        .filter { $0 != question.displayAnswer && !sameKind.contains($0) }
        .shuffled()
        .prefix(count - sameKind.count)

    return sameKind + filler
}
```

같은 답을 가진 형제 문항(3,4,5,6)이 서로를 "다른 사람"으로 세지 않도록, 뺄 때 기준을
`$0.id != question.id` 에서 `$0.displayAnswer != question.displayAnswer` 로 바꿨습니다.

## ② 스크롤이 생기면 오른쪽에 위치 막대 넣기

문제 지문 + 보기가 화면보다 길 때, 지금은 스크롤이 된다는 티가 잘 안 납니다.
화면 오른쪽에 **작은 세로 막대**를 붙여서, 스크롤이 필요한 화면에서만 나타나고
지금 어디쯤 있는지 보여주게 만듭니다.

### 새로 알아야 할 것 (`GUIDE.md`에도 추가해 뒀습니다)

- **`GeometryReader`** — 자기 자리에 실제로 얼마만큼의 크기가 주어졌는지 알아내는 뷰
- **`PreferenceKey`** — 자식 뷰(스크롤 내용)가 부모 뷰(화면)에게 값을 거슬러 올려보내는 통로. 값은 보통 위→아래로만 내려가는데, "지금 스크롤이 어디까지 왔나"는 반대 방향이라 이게 필요합니다
- **`.coordinateSpace(name:)`** — 위치를 잴 때 기준으로 삼을 좌표계에 이름을 붙이는 것

### 넣는 순서

#### ⓐ 새 파일 `KCT/DesignSystem/ScrollProgressIndicator.swift` 를 만듭니다

```swift
//
//  ScrollProgressIndicator.swift
//  KCT
//
//  역할 : 스크롤이 필요한 화면 오른쪽에 붙는 작은 위치 표시 막대
//  요점 : 내용이 화면에 다 들어오면 그리지 않는다 — 안 보이는 스크롤은 없는 것과 같다
//
//  ── 구성 ──────────────────────────────────────────────
//  ScrollProgressIndicator      트랙(연보라) + 막대(시그니처색)
//  ├─ contentHeight             스크롤되는 내용 전체 키
//  ├─ containerHeight           화면에 실제로 보이는 만큼의 키
//  └─ offset                    지금까지 아래로 스크롤한 만큼
//
//  ScrollContentHeightKey / ScrollContainerHeightKey / ScrollOffsetKey
//    스크롤 내용의 키·화면 키·스크롤 위치를 부모에게 올려보내는 PreferenceKey 셋.
//    QuestionScreen 이 이 값들을 읽어 위 세 값을 채운다.
//
//  ── 연결 ──────────────────────────────────────────────
//  불러 쓰는 곳 : QuestionScreen (지문+보기 스크롤 오른쪽)
//  기대는 것    : AppColor 뿐
//

import SwiftUI

/// 스크롤 내용의 키를 부모에게 올려보내는 통로.
struct ScrollContentHeightKey: PreferenceKey {
    static var defaultValue: CGFloat = 0
    static func reduce(value: inout CGFloat, nextValue: () -> CGFloat) { value = nextValue() }
}

/// 스크롤 뷰(화면에 보이는 만큼)의 키를 부모에게 올려보내는 통로.
struct ScrollContainerHeightKey: PreferenceKey {
    static var defaultValue: CGFloat = 0
    static func reduce(value: inout CGFloat, nextValue: () -> CGFloat) { value = nextValue() }
}

/// 지금까지 아래로 스크롤한 만큼을 부모에게 올려보내는 통로.
struct ScrollOffsetKey: PreferenceKey {
    static var defaultValue: CGFloat = 0
    static func reduce(value: inout CGFloat, nextValue: () -> CGFloat) { value = nextValue() }
}

/// 스크롤 가능한 화면 오른쪽에 붙이는 작은 위치 막대.
///
/// 내용이 화면보다 길 때만 나타납니다. 다 보이는 화면에서는 그려도 의미가 없어
/// 스스로 숨습니다 (``isScrollable``).
struct ScrollProgressIndicator: View {
    let contentHeight: CGFloat
    let containerHeight: CGFloat
    let offset: CGFloat

    private var isScrollable: Bool {
        contentHeight > containerHeight + 1 // 부동소수점 오차 방지
    }

    /// 트랙 안에서 막대가 차지하는 비율. 보이는 만큼 ÷ 전체.
    private var thumbRatio: CGFloat {
        guard contentHeight > 0 else { return 1 }
        return min(1, containerHeight / contentHeight)
    }

    /// 스크롤한 비율(0~1). 다 내리면 1.
    private var scrollProgress: CGFloat {
        let scrollable = contentHeight - containerHeight
        guard scrollable > 0 else { return 0 }
        return min(1, max(0, offset / scrollable))
    }

    var body: some View {
        if isScrollable {
            GeometryReader { geo in
                let trackHeight = geo.size.height
                let thumbHeight = max(24, trackHeight * thumbRatio)
                let maxTravel = max(0, trackHeight - thumbHeight)

                ZStack(alignment: .top) {
                    Capsule()
                        .fill(AppColor.softBackground)
                        .frame(width: 5, height: trackHeight)

                    Capsule()
                        .fill(AppColor.signature)
                        .frame(width: 5, height: thumbHeight)
                        .offset(y: maxTravel * scrollProgress)
                }
            }
            .frame(width: 5)
        }
    }
}

#Preview {
    HStack {
        Spacer()
        ScrollProgressIndicator(contentHeight: 900, containerHeight: 400, offset: 200)
    }
    .frame(height: 400)
    .padding()
}
```

        .coordinateSpace(name: "questionScroll")
        .background(
            // 화면에 실제로 보이는 만큼(뷰포트)의 키를 재서 올려보낸다.
            GeometryReader { containerGeo in
                Color.clear
                    .preference(key: ScrollContainerHeightKey.self, value: containerGeo.size.height)
            }
        )
        .onPreferenceChange(ScrollContentHeightKey.self) { scrollContentHeight = $0 }
        .onPreferenceChange(ScrollContainerHeightKey.self) { scrollContainerHeight = $0 }
        .onPreferenceChange(ScrollOffsetKey.self) { scrollOffset = $0 }

        ScrollProgressIndicator(

            containerHeight: scrollContainerHeight,
            offset: scrollOffset
        )

### 왜 이렇게 짰나

- **`GeometryReader` + `PreferenceKey` 두 벌을 쓴 이유** — 하나는 "내용 전체가 얼마나
  긴가"(스크롤 안쪽에서 잼), 하나는 "화면에 실제로 보이는 건 얼마인가"(스크롤 바깥
  틀에서 잼)를 재는 겁니다. 둘을 나눠 재야 "전체가 보이는 것보다 길 때만" 막대가
  나타나게 만들 수 있습니다.
- **막대 최소 높이를 24로 둔 이유** — 내용이 아주 길면 막대가 1~2pt로 작아져 안 보일
  수 있습니다. 최소 크기를 보장해 항상 손가락이나 눈으로 알아볼 수 있게 했습니다.
- **회색 스크롤바를 그냥 켜지 않고 직접 그린 이유** — SwiftUI 기본 스크롤 인디케이터는
  스크롤하는 동안만 잠깐 보이다 사라집니다. 어머니가 "여기 더 있다"는 걸 **스크롤하기
  전에** 알아채시려면, 화면에 계속 떠 있는 막대가 낫습니다.

### 다 넣고 확인할 것 (②)

1. 빌드가 되는지 봅니다.
2. 보기가 4개라 길어지는 4지선다 문제에서, 화면보다 내용이 길면 오른쪽에 막대가
   뜨는지 봅니다.
3. 내용이 짧은 O/X 문제 같은 데서는 막대가 **안 뜨는지**(공간을 차지하지 않는지) 봅니다.
4. 스크롤을 내려 보면서 막대가 같이 아래로 움직이는지 봅니다.

## ③ 텍스트필드 문구 변경

**넣을 위치**: `KCT/Screens/QuestionScreen.swift`, `freeTextField` 안

**지금 코드**

```swift
if session.userAnswer.isEmpty {
    Text("답을 입력하세요")
```

**바뀔 코드**

```swift
if session.userAnswer.isEmpty {
    Text("터치하여 입력하세요.")
```

## 다 넣고 확인할 것 (전체)

1. 빌드가 되는지 봅니다.
2. 애국가 작곡자(안익태), 고구려 시조(주몽) 문제를 2지선다로 여러 번 띄워서 **오답이
   매번 인물인지** 봅니다.
3. 같은 문제들을 4지선다로도 띄워서, 인물 2명 + 다른 데서 1명이 섞이는지(3명 다
   인물은 아직 못 됩니다 — 인물 문항이 3개뿐이라서 그렇습니다) 봅니다.
4. 스크롤 막대가 필요한 데서만 뜨는지 확인합니다.
5. 직접입력 문제에서 빈칸에 "터치하여 입력하세요."가 나오는지 봅니다.

다 넣으셨다고 알려 주시면 파일을 열어 대조하고, `QuestionCatalog.swift` 맨 위 요약과
`SessionPlanning.md` 도 그때 같이 반영하겠습니다.
