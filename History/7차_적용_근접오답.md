# 2지선다·4지선다 어렵게 하기 (격려용 자리는 예외)

> 원본 계획: `7차_계획_근접오답.md` (옵션 C로 승인됨)
> 다 넣으면 지워도 되는 임시 메모입니다.

## 뭘 바꾸나

지금은 오답 보기를 **같은 계열만 뺀** 정답 전체에서 뽑습니다 (`answerPool(excludingCategory:)`).
계열이 다르면 대개 한눈에 답이 보여서 너무 쉽습니다.

바꾼 뒤에는 **회차 첫·마지막(격려용) 문제만** 지금처럼 쉬운 풀을 쓰고,
**나머지 문제는** 정답과 같은 `AnswerKind`(같은 종류 — 인물끼리, 장소끼리, 사건끼리)
안에서만 오답을 뽑습니다. 헷갈릴 만한 오답이라 더 어렵습니다.

## 넣는 순서

### ① `KCT/Data/QuestionCatalog.swift` — 새 함수 하나 추가

**넣을 위치**: `answerPool(excludingCategory:atLeast:)` 함수 바로 아래

```swift
/// 같은 종류(``Question/kind``)로만 좁힌 정답 모음.
///
/// 계열만 다르면 오답이 한눈에 티가 나서 너무 쉽습니다. 「단군왕검」의 오답으로
/// 「한글」이 나오면 볼 것도 없이 지워지지만, 같은 인물(kind: .person)인
/// 「이성계」가 나오면 실제로 생각해야 합니다.
///
/// - Note: 남은 보기가 `minimum` 보다 적으면 전체 모음으로 되돌아갑니다 —
///   그 종류의 문제가 몇 개 없을 때 보기가 비어 화면이 깨지는 것을 막습니다.
func answerPool(preferringKindOf question: Question, atLeast minimum: Int = 3) -> [String] {
    let narrowed = Set(
        questions
            .filter { $0.kind == question.kind && $0.id != question.id }
            .map(\.displayAnswer)
    )
    return narrowed.count >= minimum ? Array(narrowed) : answerPool
}
```

`Question.self`가 아니라 `question.id`로 자기 자신을 빼는 이유: `answerPool(excludingCategory:)`는
`displayAnswer`만 모으기 때문에 애초에 자기 문제가 껴 있어도 `Question.makeChoices`가
나중에 정답을 풀에서 한 번 더 빼므로 문제가 없었습니다. 여기서는 미리 빼서 그 우연에
기대지 않게 했습니다.

### ② `KCT/Session/SessionBuilder.swift` — `shapeRound(_:progressByID:focusByID:)` 안, `QuizItem.make` 호출부 수정

**지금 코드**

```swift
return QuizItem.make(
    question,
    mode: mode,
    // 같은 계열을 뺀 보기만 쓴다 — 근접 오답을 우연에 맡기지 않는다.
    answerPool: catalog.answerPool(excludingCategory: question.category),
    affectsProgress: !isBookend,
    focus: focusByID[question.id]
)
```

**바뀔 코드**

```swift
return QuizItem.make(
    question,
    mode: mode,
    // 격려용(회차 첫·마지막)은 쉬운 풀, 나머지는 같은 kind로 좁혀 헷갈리게 만든다.
    answerPool: isBookend
        ? catalog.answerPool(excludingCategory: question.category)
        : catalog.answerPool(preferringKindOf: question),
    affectsProgress: !isBookend,
    focus: focusByID[question.id]
)
```

`isBookend`는 바로 위에서 이미 계산해 둔 값을 그대로 씁니다 — 새로 만들 것 없습니다.

### ③ `QuestionCatalog.swift` 맨 위 요약 주석에 한 줄 추가 (이건 제가 바로 고칠 부분이라, 코드를 넣어 주시면 그때 같이 반영하겠습니다)

```
//  ├─ answerPool(excluding:)   같은 계열을 뺀 정답 모음 — 근접 오답을 없앤다
//  ├─ answerPool(preferringKindOf:)   같은 종류로 좁힌 정답 모음 — 더 헷갈리게 만든다
```

## 왜 이렇게 짰나

- **`category`가 아니라 `kind`를 쓴 이유** — `category`(단원 계열)는 지금 문제집이 30문항뿐이라
  같은 계열도 서로 안 헷갈리는 경우가 많습니다. `AnswerKind`(인물/장소/사건/사물 같은 답의 **종류**)가
  더 촘촘한 축이라 "이성계 vs 단군왕검"처럼 진짜 헷갈리는 짝이 나옵니다.
- **격려용 자리는 그대로 둔 이유** — 회차 첫·마지막은 "계속하고 싶어지게" 만드는 자리라
  원래부터 쉬운 문제였습니다 (`isBookend` → 항상 `.binaryChoice`, `affectsProgress: false`).
  거기까지 어렵게 만들면 그 자리의 원래 목적이 사라집니다.
- **`atLeast minimum` 기본값을 그대로 3으로 둔 이유** — `excludingCategory`와 같은 안전장치입니다.
  어떤 `kind`는 문제 수가 적을 수 있어서, 그럴 땐 전체 모음으로 자동으로 되돌아갑니다.

## 다 넣고 확인할 것

1. 빌드가 되는지 봅니다.
2. 인물(kind: `.person`)인 문제를 4지선다로 여러 번 띄워 보고, 오답 네 개가
   **매번 다 인물**인지 봅니다 (장소나 사물이 섞이면 안 됩니다).
3. 문제 수가 적은 `kind`(장소·유산 등)의 문제도 화면이 안 깨지고 보기가 채워지는지 봅니다
   — 이건 `minimum`보다 적어서 전체 모음으로 되돌아가는 경우입니다.
4. 회차 첫 문제와 마지막 문제는 여전히 쉬운(계열만 다른) 보기로 나오는지 봅니다.
5. 실제로 어머니께 몇 회차 풀어 보시게 하고 체감 난이도가 어떤지 봅니다.
